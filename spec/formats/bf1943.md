# Battlefield 1943 as a source

Battlefield 1943 (Xbox 360, Frostbite 1.5) is where the Pacific War's assets come from: its bundles are read from the
user's own extracted copy, converted by the suite's readers and OPFOR's WW2 tools, and never shipped. This file is the
source side: where the suite reads BF1943 from, what its bundle set and levels are, and what differs from BFBC2 at the
container and class level; the formats it shares with BFBC2 are specified in their own files and indexed here.
Written by round SPG2 (2026-11-22).

## 1. The source

### B43-SRC-1: The suite reads BF1943 from the user's extracted copy, read only

Status: **implemented** · Variants: BF1943

`bf1943import.default_source()` is `BF1943_XENON` when set (unchecked), else Project Rising Sun's extraction beside the
suite (`operation-rising-sun\work\extracted\dist\xenon`); the bundle reader is the BF1943 tool suite's
(`bf1943-tool-suite\bf1943-fbrb-tool\fbrb1943.py`). OPFOR's WW2 tools open the same source. The source and the game
copy are never written: converted assets go to OPFOR's `work\` and are installed from there; BF1943's data is EA
content and is never committed.

## 2. Bundles and levels

### B43-BNDL-1: BF1943's bundle set: 85 bundles, no registry files

Status: **observed** · Variants: BF1943

The extraction holds 85 FBRB bundles and `config.zz`, with no `package.mft` and no `bundleManifest`: per level
`reduced-level`, `terrain`, `ui/multiplayer` and `vo/<lang>` for six languages (de, en, es, fr, it, jp); one shared
`levels/levels-common` (5,151 entries); `async/startup`, `async/ondemand_sounds`, `async/ondemand_awards`, 22
`async/weapon/<name>`; `streaming_sounds`, `vo`, `build_overlay`, `logomusic`; 10 `menu/*`. Against BFBC2's kinds
(BNDL-KIND-1): the level bundle is `reduced-level`, the UI bundle `ui/multiplayer`; there are no `ingame`, `loader` or
`streaming_vo_<lang>` bundles; Polish and Russian are absent, Japanese present.

### B43-BNDL-2: The same container; the same stored / compressed split

Status: **observed** · Variants: BF1943

### B43-WPN-1: 12 of BF1943's 22 weapon bundles have a BFBC2 namesake

Status: **observed** · Variants: PC, BF1943

BFBC2's stock Dist `async/weapon` (323 bundles) has 12 of BF1943's 22 weapon bundle names (`expack`,
`jap_shingunto_knife`, `jap_type97_gren`, `m18_jap`, `m1911a1`, `m1garand`, `nambu100`, `nambu_pistol`, `thompson`,
`type5`, `type5_rgl`, `us_pineapple_gren`: DICE's campaign weapons, WPN-WW2-1); the other 10 (`expack_jap`, `k98`,
`m18`, `m1garand_bayonet`, `m1garand_rgl`, `springfield1903`, `type5_bayonet`, `us_longknife_knife`, `wrench`,
`wrench_jap`) are BF1943's alone.

## 3. Classes

### B43-DBX-1: The class differences DICE resolved, and BF1943 classes BFBC2 lacks

Status: **observed** · Variants: PC, BF1943

The binary DBX is the same. Where DICE brought BF1943's data into BFBC2 it renamed `Mesh1p` / `Mesh3p` to
`Meshes1p` / `Meshes3p`, removed the persistent-weapon instances embedded in weapon partitions, moved
`objects/soldiers/common/beach/defaulthaloaimer` to `objects/soldiers/common/defaulthaloaimer` (keeping the GUIDs) and
recomputed every `BoneFakePhysicsData.BoneId` for BFBC2's skeleton (24 of 24 match DICE's, 15 differ from BF1943's);
BFBC2 ships animation trees compiled (ANIM-TREE-1). BFBC2 has no class for BF1943's air raid (`AirRaidEffectsData`,
`TeamVehicleProjectileEntityData`), `CarHornComponentData`, `ScorePartComponentData`, nor the modes' `DmzEntityData`,
`RepairStationEntityData`, `HotZoneEntityData` (GAME-AS-1): those features need the game module.

### B43-HK-1: Havok 4.6.1 carries no reflection; layouts come from data

Status: **observed** · Variants: BF1943

BF1943's Havok 4.6.1 packfiles have an empty `__types__` section and its executable keeps no class reflection, so the
4.6.1 layouts were reconstructed from data (HAVOK-V461-1). The oracle pairs of BF1943 / BFBC2 physics files for the
same vehicles: Zero 170,112 / 169,492 bytes, Kurogane 106,583 / 106,503, Corsair 88,386 / 87,848.
