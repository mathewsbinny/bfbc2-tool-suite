# The suite's documentation: where everything lives

This page indexes every document in the repository: what kind of document lives where, and the rules that keep them from overlapping.

## Two homes

- **This repository** holds documents about the suite itself: how to use each tool, how the code is built, and the normative rules the code implements (`spec/`).
- **battlefield-opfor's knowledge base** (`docs/`) holds the narrative: plans, goals, decisions, research write-ups and task lists. The suite cites it as `bfo:docs/...` and it cites the spec by rule id.
- **Decompiler-derived research is private.** It lives in the private decompilation repository, which the suite cites as `private:...` (`spec/README.md`, "The decompiled database"; `tools/decomp/README.md`).

A plan, a decision or a research narrative written here belongs in the knowledge base. Leave a one-line pointer here.

## Rules for the documents

1. **One canonical place per fact.** A second document that needs it links to the first, and doesn't copy it. Normative statements go in `spec/`, with a rule id; a tool's README says what the tool does and points at the rule.
2. **Names.**
   - Every folder's main document is `README.md`.
   - `FORMAT.md` only for an evidence record behind a spec chapter.
   - A dated document carries its date in its title, and in its file name when the name would otherwise clash.
3. **Current truth or clearly history.**
   - A tool's README describes the tool as it is. What changed and when is the CHANGELOG's job; the measurements are BENCHMARKS'.
   - A retired tool is described only in `RETIRED.md` and dated history.
   - A finished audit moves to `docs/archive/` with its outcome.
4. **Citations.** Write `bfo:docs/...` for the knowledge base, `private:...` for the private repository, and repository-relative paths for the suite. Never write an absolute path from someone's machine.
5. **Cited documents.** `spec/trace.py --check` resolves every `[doc: path:lines]` citation. It does not see a line that moved and still exists, so an edit to a cited document stays line-neutral, or re-lines its citations in the same commit.
