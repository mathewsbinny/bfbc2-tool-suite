# Roadmap

The one place for the suite's priorities and its queue of rounds. Keep it current: a round moves to **In progress**
when its branch starts, to **Done** (with a one-line result) when it is merged to `main`, and the priority order
changes only when the user changes it. Each round's evidence stays where it is: its commit messages, its section of
`rust/BENCHMARKS.md`, and `bfbc2-map-editor/EDITOR_ARCHITECTURE.md` for the editor. Released versions are in
`CHANGELOG.md`; how a round reaches `main` is in `RELEASING.md`.

Last updated: 2026-11-22 (round PYI). Version: 0.13.0 (`VERSION`; a merge that removes something releases the next
minor: `RELEASING.md`).

## Python left

Every `bfbc2.exe` command parses its arguments in Rust, but some still hand their main job to Python (round PYI:
`navkit` build / all / apply on a NavKit base / sample, `navparity run`, `navregress`, `hpdview`, `sample_all`,
`harness run`, texqa's sheets, renderqa's draws, `xdiff`, `bf1943import` import / check, `dbxparity`, `portparity`);
the rest is Python libraries and pipeline code. Per file: `PYTHON_STATUS.md` (generated, checked). Each folder has the
round that retires it (the user, 2026-11-22; audit AU5 ARC-13; line counts of non-test Python on 2026-11-21, before
NK1-NK3). A round that retires a folder's code deletes it (RETIRED.md for a tool, BENCHMARKS / CHANGELOG for a twin).

File by file: `PYTHON_STATUS.md` (and `python_status.json`), generated by `python rust\python_status.py` from its
table - each `.py` file's kind, status (live, partly, twin, ported, retired-pending, stays, test), Rust counterpart,
callers, retiring round and a note, with totals by status and folder. `tests/test_repo.py` fails when a `.py` file is
added or deleted without its row, so update the table (and regenerate) in the round that adds, ports or retires one.
